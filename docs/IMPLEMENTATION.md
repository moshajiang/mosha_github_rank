## 1. 已落实的技术取舍

- Python + FastAPI、React + TypeScript + Vite，SQLite 保存事实与快照。
- 数据库直接使用标准库 sqlite3 与 schema version，不引入 SQLAlchemy/Alembic；已实现 v1→v2 显式迁移，保留历史数据并拒绝打开更新版本数据库。
- 趋势曲线用原生 SVG，减少单条曲线对额外图表包的依赖，缺少日期断线显示。
- API 和前端可以由一个本机服务提供；数据任务通过独立 CLI 执行。Docker Compose 另设 scheduler 进程，沿用同一数据卷。
- 模型尚未配置，当前为原文与中文事实模板；第二阶段已实现可选 Ollama 摘要适配、引用校验、缓存失效与每日上限，真实模型质量和预算评估尚待进行。
- 首轮未认证 GitHub API 实测触发限流，已增加同一批次停止 API 请求及公开页面降级；仅从结构化 JSON 读取精确计数，缩写计数不得写入快照。
- 页面降级缺失的推送时间、语言、许可证等字段不猜测；资源扫描只保留可验证路径并标记 partial，暂不声明完整扫描。
- Release API 限流时使用同仓库的官方 `releases.atom`；Atom 只给更新时间而没有发布时间时保留时间未知，不将更新时间冒作首次发布。

## 2. 分阶段状态

### 阶段一：基础与真实采集（已完成首轮）

已实现数据库、配置、HTTP 缓存、限流隔离、任务锁、仓库快照、资源路径识别、RSS/Atom/HTML 资讯、Release、来源和任务报告。已完成小样本真实采集，规模与状态见 [验证报告](VALIDATION.md)。

首轮样本不是最初计划的 100 个仓库，原因是当前没有 GitHub Token、公共 API 额度已耗尽。已跑通 12 个真实仓库的精确计数降级路径；扩量、搜索覆盖与 48 小时稳定性仍待验证。

### 阶段二：核心浏览闭环（已实现并验证基础流程）

包含发现首页、热门/潜力、7/30 天窗口、分类与关键词筛选、Agent 仓库/资源目录、资讯筛选、项目详情、日曲线、浏览器收藏、榜单归档与 Markdown/JSON 导出。

排名计算已用隔离数据库覆盖缺端点、负增长、样本不足和平均秩等情况；生产库只含真实首次采集数据，正式增长榜和潜力分等待历史积累。

### 阶段三：持续验证与增强（已完成一部分）

已完成：100 个真实仓库扩量，6 条搜索查询均有真实返回并记录截断范围；公开 API 与页面降级混合采集；官方 MCP 列表补充候选；DeepMind 原生 RSS 修复；语言/Star 组合筛选与一致导出；来源本机启停；数据库 v1→v2 迁移；Ollama 摘要任务接口。当前 100 个仓库中 5 个来自 API、95 个来自公开页面，不能据此声称全量元数据和资源扫描完成。

下一步：

1. 在稳定运行环境增加 API 完整元数据的覆盖比例，验证未截断的资源识别；当前 100 个仓库已验证真实采集，但大部分依赖页面降级。
2. 持续运行 48 小时，核对按源轮询、每日任务、源失效与恢复；该过程尚未完成，不用测试夹具代替真实观测。
3. 配置实际模型后，用项目/资讯样本评估已实现的 Ollama 中文摘要、事实准确性、耗时和资源消耗。
4. 扩展兼容生态证据及资源去重，改进多语言跨来源事件聚合。目前只做强 ID 和保守的同日同标题匹配。
5. 上游未提供精确时间的新闻保留日期精度或未知状态；HTML 来源解析变化持续回归验证。
6. 完整周/月增长、双周期潜力评分成熟后，比较评分基线并调整权重；自然周/月刊、资讯事件人工修订、撤回识别、账号和推送继续后置。

### 阶段四：项目维护与身份连续性（2026-10-31 已实现）

新增单仓库即时采集 CLI，手动候选不受常规批次名额阻塞；采集成功后纳入已有跟踪池。分类和 Agent 标签人工覆盖独立于原始元数据保存，刷新后仍有效；排除/恢复应用到实时项目、榜单、参照样本和资源目录，保留历史和旧归档。所有修订带说明及前后值审计，支持恢复最新自动规则。

新增 schema v3 别名表：按实际返回的 GitHub 数字 ID 识别改名，旧详情和历史地址解析到当前项目，资源保留 commit 路径。当前名称复用优先，避免把两个 ID 合并。真实采集已验证 `tiangolo/fastapi` → `fastapi/fastapi`。命令和边界见 [项目维护说明](CURATION.md)。

## 3. 首版运行边界

本轮运行增强（2026-10-31）：schema v4 添加调度单实例状态、独立心跳、来源健康/事件；新增 Windows 采集启停入口、CLI status/stop/once，运行面板展示下一检查和仓库任务计划、过期/故障/恢复。中断接管只处理旧调度明确拥有的锁和任务；与手动采集共用 collection 锁。说明见 [OPERATIONS.md](OPERATIONS.md)。短时生命周期测试已完成，48 小时持续验证仍待完成。

该实现定位为本地/自托管工作台。公共写入管理接口未开放，采集由本机命令或 scheduler 执行；刷新页面只读取本地数据库。服务默认只监听本机。

任务锁为两小时租约，当前小批次任务应在该窗口内完成；扩至长任务时应增加租约续期。日志和接口不输出 Token。

当前 schema v3 支持已观测旧 owner/name 别名、人工分类覆写及审计；网页提供来源与排除状态提示，管理仍经本机 CLI。事件拆分/合并及网页管理表单尚未实现。

每日采集优先刷新已跟踪仓库，再在批次额度内接纳新候选；达到批次上限时记录 deferred_repositories。当前默认每批最多 200 个，需根据实际网络与 Token 额度调整，不能无限扩大跟踪池却承诺全部每日更新。

SQLite 备份通过 backup API 一致性复制；恢复在停机后使用备份文件，不提供自动覆盖生产数据的命令。
