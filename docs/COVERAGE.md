# 数据覆盖体检

更新：2026-11-19。用于回答“哪些数据仍缺失、为什么不能入榜、先刷新哪些项目”。报告读取一个 SQLite 一致性视图，不发起上游请求，不写入采集、个人状态或榜单归档。

~~~powershell
.\.venv\Scripts\python.exe -m github_rank.cli coverage
.\.venv\Scripts\python.exe -m github_rank.cli coverage --limit 10 --output data/coverage.json
.\.venv\Scripts\python.exe -m github_rank.cli coverage --format markdown --output data/coverage.md
~~~

输出文件必须尚不存在，扩展名须对应 .json / .md；建议每次加上日期或批次。limit 仅控制待刷新候选数量（0—100），不会改变全库汇总分母。GET /api/coverage?limit=20 提供同口径只读 JSON。

## 统计内容

- 项目：跟踪/人工排除数、元数据新鲜/过期数、最近数据来源、未记录字段。
- 历史：真实快照数、实际有观测的 UTC 日期、无任何观测的日期数、当前端点覆盖。日期从最早观测到报告日期计算，不补造关机期间的数据。
- 榜单：7/30 天热门与潜力资格，以及可重叠的机器原因码和中文解释。与实际评分复用同一计算器，未改变原有门槛或权重。
- 资源：纳入/排除记录、文件 hash 覆盖、仓库扫描完整/部分/未扫描，以及扫描过期/无日期的数量。
- 完整扫描证据：最近一次完整扫描识别至少两项资源的仓库数，可与本轮状态和扫描新鲜度对照。
- 资讯与运行：来源新鲜、过期、暂停和错误状态；当前调度心跳；摘要缓存数量。

有新鲜快照（36 小时内）时使用最近实际观测作为统计端点，与应用的每日快照方式衔接；旧快照已过期时则按当前时间检验，避免历史上完整的旧区间被误解为当前就绪。每个窗口单独返回实际 as_of。

“最近观测新鲜”只表示最后一条记录新鲜，不能代表全库。当前端点覆盖和元数据过期项目数需要一起查看。全局某天有一个快照，也不表示所有项目当天都有观测。

语言可能未标注，许可证可能未声明；缺字段并不直接证明采集失败。data_sources 反映最近一轮来源，不代表永久的元数据质量。资源 complete 只限该次默认分支、支持的清单格式和扫描预算，不能代替完整兼容性测试或保证未来未变化。

## 后续补采

候选排除人工排除、归档、禁用与 Fork 项目，先按是否过期、缺口数量、最早更新时间和稳定 ID 排序。每项给出当前名称、ID、链接和原因；不会自动执行它们。

可按当前计划定向补扫已跟踪的 Agent 仓库。预览会列出优先处理的仓库及已有资源数。 [补扫说明](AGENT_RESOURCES.md#定向补扫)

~~~powershell
.\.venv\Scripts\python.exe -m github_rank.cli projects rescan --dry-run
.\.venv\Scripts\python.exe -m github_rank.cli projects rescan --limit 10
~~~

补扫写入当前采集结果。API 限流或本批资源请求额度用尽时，未处理项目显示为待续。
