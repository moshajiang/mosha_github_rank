## 1. 定位与内容

用户进入“AI 前沿资讯”，可以快速了解最近发生的技术进展，并跳转原文、论文、模型或 GitHub 项目。资讯不要求必须有开源仓库，避免遗漏闭源模型与重要研究发布。

首版覆盖六类：

- 模型发布：基础模型、推理能力、开源权重及重要版本更新。
- AI Agent：框架、编程助手、工具调用、MCP、插件、Skills。
- 前沿研究：训练/推理方法、长上下文、记忆、对齐与评测。
- 多模态与具身智能：图像、视频、语音、机器人。
- 开源与工程：推理框架、数据集、部署和开发工具。
- 产业与治理：有明确技术或开发者影响的重要动态；普通营销、融资和重复宣传默认不进入重点流。

首屏提供“最新”和“重点”两个视图，以及最近 24 小时/7 天/30 天切换。24 小时视图没有新内容就展示空状态和上次成功同步时间，不拿旧文填成新资讯。

## 2. 来源与接入

优先级：官方发布/原始论文/项目 Release → 研究聚合入口 → 可选专业媒体与社区发现。原始发布说明能证明“作者发布或声称了什么”，不自动证明其性能宣传经过独立复现。

首批候选来源：OpenAI、Anthropic、Google DeepMind 的官方资讯；Qwen 新站与其他国内模型团队的官方渠道在开发时核实；arXiv 分类 RSS/Atom；Hugging Face Papers；本站已经跟踪的 AI 仓库 Releases。各来源的调查链接见 [调研增补](RESEARCH.md)。

MVP 至少接通三个经验证的官方资讯源、一个论文源和 GitHub Release 源。接入顺序为可用 RSS/Atom、正式 API、允许访问的公开页面适配器；没有公开 feed 的来源不虚构订阅地址。需要专门授权或访问受限的源先保持停用状态，其他源照常运行。

来源配置保存名称、主页、源类别、采集方式、允许的域名、轮询间隔、启用状态、解析器版本与最近成功时间。源码配置文件管理，首版不提供公开的任意网址抓取入口。

默认对支持较频繁更新的来源每 30 分钟检查一次，使用 ETag/Last-Modified、请求预算和退避；论文源按其发布节奏配置。来源无更新、限流或任务延迟时如实展示状态，不承诺实时覆盖全网。

冷启动默认回填近 30 天可获得的内容，展示原始发布日期；不修改原始时间来增加“今日资讯”。论文源优先读摘要和元数据，不把下载、转换每篇 PDF 作为资讯更新前提。

## 3. 卡片与详情

卡片显示中文标题、80—180 字摘要、主题、来源、发布时间、生成方式、原文链接，以及存在证据的论文/模型/代码入口。Agent 资讯使用固定标签便于集中浏览。

摘要包含“发生了什么”和“与开发者有什么关系”。后者如含判断，标为“简要解读”；性能、成本、兼容性等结论附依据，作者自述用“作者称”，不把预印本等同于同行评审成果。

详情页展示主来源、其他相关报道、内容更新记录和关联项目。正文以本站短摘要为主，不批量转载全文；模型输入与正文存储范围遵守来源使用条件。没有模型配置时展示原标题、可获得的原始摘要和链接，并标明语言及摘要方式。

原始 `published_at`、来源 `updated_at`、本站 `first_seen_at`、`fetched_at` 分开保存。保留原始时区和时间精度，UI 统一北京时间；没有可信发布时间的内容显示“发布时间未知”，按首次发现排序并单独标记，不能伪装成最近 24 小时内发布。

只更新抓取时间不令文章重新登顶。实质性更新显示更新标记，原发布时间不变。来源更正/撤回时保留记录、更新摘要并标记；暂时抓取失败不推断为撤回。

## 4. 去重与重点筛选

两层去重：先通过 feed GUID、规范化 URL、arXiv ID、Release ID 去除同条重复记录；再通过实体、版本、标题与时间窗口聚合“同一事件的多篇报道”。

规范化仅删除已知跟踪参数，保留可能有内容语义的查询参数；canonical 和重定向关系需校验。标题相似不能单独决定合并，模型新版本与后续独立研究不合成一个事件。自动匹配不确定时保留分立，允许配置人工合并/拆分覆盖。

“最新”以可信原发布时间倒序，时间未知项独立展示。“重点”为可解释的筛选排序，初版依据技术事件类型、主题相关性、是否有原始证据、是否有可用论文/模型/代码和时间衰减，采用版本化规则；支持人工置顶并显示“编辑精选”。

不以转载数量直接计分，不生成无法解释的“全网热度”。Hugging Face/GitHub 的热度信号分别标注渠道和采样时间，缺失就不展示。首版不混算新闻分与仓库潜力分。

## 5. 与榜单、Agent 专栏联动

- 资讯明确提供 GitHub 链接时，规范化仓库 ID；已跟踪项目直接关联，未跟踪项目进入候选队列并开始快照。
- 论文使用 arXiv ID/DOI，模型使用官方标识和链接进行匹配；仅名称相似不足以确定关联。
- 项目详情增加“相关资讯”；Agent 专栏增加“最新动态”；资讯卡片提供“查看关联项目”。
- 只有正文或结构化元数据有可靠资源路径时才关联具体 Skill/插件；否则只关联仓库。
- 收藏统一支持项目、资源与资讯，本地记录实体类型和 ID；导出同时包含中文摘要和原始链接。

## 6. 处理链路与验收

```text
来源轮询 → 解析与时间归一化 → 条目去重 → 事件聚合
        → 主题分类 → 中文摘要/原文降级 → 实体关联 → 发布资讯 API
```

复用现有采集重试、缓存、摘要适配器与任务日志；资讯任务有独立预算和锁。摘要缓存键包含条目版本 hash、语言和提示词版本。页面解析器失效时停用该源并保留已采内容，避免发布菜单或错误页面作为资讯。

必要验证覆盖：相对链接与重复 GUID、时区/日期精度、未知时间、旧文首次抓取、内容更新、同事件转载、不同版本不误合并、来源失效、限流与模型降级。时间窗口按可信发布时间筛选，不按抓取时间替代。

首版验收：

1. 导航中有独立“AI 前沿资讯”，首页和 Agent 专栏有相应入口。
2. 首批真实来源可定时更新，原文可打开，来源状态和同步时间可见。
3. 支持时间、主题、来源、关键词筛选，最新/重点视图有明确排序依据。
4. 同事件跨源报道可聚合并保留原始链接，更新和撤回状态可追溯。
5. 有依据的中文摘要与事实/解读区分可见；无模型时仍可正常浏览。
6. 资讯与项目通过可验证链接关联；新增仓库不伪造历史数据。

预计增加 2—3 个工作日，纳入主方案后的首版总估算为 9—14 个工作日。实时推送、社交平台全网抓取、自动长篇研报和个性化新闻推荐留待后续。
