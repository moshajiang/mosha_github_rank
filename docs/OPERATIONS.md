# 定时采集与运行面板

更新：2026-10-31。网页服务和采集进程分别启停，数据通过同一个 SQLite 数据库共享。网页刷新只读取本地数据。

## 日常使用

首次安装完成后：

1. 双击根目录 `启动.cmd` 打开网页。
2. 双击 `启动采集.cmd` 开始后台定时采集。
3. 在网页打开“数据源与同步状态”，查看调度、来源和任务记录。
4. 双击 `停止采集.cmd` 停止采集；网页服务继续运行。
5. 双击 `关闭.cmd` 关闭网页服务；采集进程单独管理。

两个采集入口都会读取根目录 `.env`，重复启动复用同数据库的活动调度。运行日志在 `data/scheduler.log`，快捷入口的进程记录在 `data/scheduler-process.json`。管理入口核对工作区、PID 创建时间和调度实例 ID，不按进程名称批量结束 Python。

“停止”是协作式请求：完成当前网络请求后在后续采集边界退出。超过快捷入口等待时间时提示“正在停止”，不会强制结束正在写入的任务。模型摘要调用已开始时可能需要等待该次摘要批次结束。未由此入口启动的 CLI/容器调度可使用下方管理命令。

没有注册 Windows 开机任务；电脑关闭、休眠或进程退出后不继续运行。长期采集需要保持机器运行，或使用已经提供的服务器/容器部署方案；Docker 运行仍需在实际环境验证。

## 命令行

```powershell
# 前台运行；默认每 60 秒检查一次到期任务，最小检查间隔 30 秒。
.\.venv\Scripts\python.exe -m github_rank.cli schedule
.\.venv\Scripts\python.exe -m github_rank.cli schedule --status
.\.venv\Scripts\python.exe -m github_rank.cli schedule --stop
# 只运行一轮到期检查，完成后退出。
.\.venv\Scripts\python.exe -m github_rank.cli schedule --once
```

CLI 读取进程环境变量；请与网页使用相同的 `GITHUB_RANK_DB`、`GITHUB_RANK_CONFIG`。`schedule --once` 同样可能执行全量仓库采集，并非只检查健康。

每日全量任务在北京时间 08:00 后执行；启动时已经过 08:00 且当天没有完成记录，会立即补跑。当天 `all` 任务为 ok/partial 时视作已执行，避免重启后不断重复整批；部分失败明细保留在任务报告中，可手动补采。其他检查轮次只处理各自到期的资讯源。Release 随全量任务执行。

空配置不代表空跟踪池：数据库中已有项目仍会被每日任务刷新。需要完全隔离的空任务测试时，必须使用独立空数据库；页面验收副本另以明确标注的 QA 任务跳过全量刷新，不污染生产数据。

## 面板口径

只读接口 `GET /api/runtime-status` 返回调度心跳、下一次检查、每日仓库任务计划、来源故障/恢复事件及仓库过期提示。网页面板打开时每 15 秒刷新这些状态与来源、任务记录。

- **未启动 / 运行中 / 采集中 / 正在停止 / 已停止 / 心跳中断 / 异常退出**：分别表示实际保存的调度状态。心跳每 5 秒续写；活动状态超过 90 秒未续写时标记中断，不继续宣称在线。
- **下次检查**：本轮完成后安排，不保证此时一定执行上游请求；各来源有独立轮询间隔。停止或离线时不显示未来任务承诺。
- **来源状态**：last_success 表示上次成功，freshness 另外表示数据是否过期。超过 `max(来源间隔×3, 60分钟)` 未成功即标为过期；Release 使用每日间隔。来源暂停时不安排下一次检查。
- **故障和恢复**：首次进入失败状态记录事件，连续失败只累加次数，恢复成功另记事件；不会因为暂停或正常重复采集制造恢复事件。迁移之前的历史事件不补造。
- **仓库过期**：任一已跟踪仓库超过 36 小时未更新即提示，不能仅用最新一个项目的时间代表整个跟踪池。

单数据库只允许一个有新鲜心跳的调度。心跳过期后新实例可以接管，并将明确属于旧实例的运行任务标为 interrupted、释放其 collection 锁；手动采集锁不受影响。旧实例恢复后会识别所有权变化并停止后续请求。正常手动采集占用共享任务锁时，调度记录 deferred，下一轮再检查。

## 验证与限制

数据库 v3→v4 添加调度状态、来源健康和事件表，升级前已做生产库一致性备份。原有仓库、快照、资源、资讯、归档及人工修订保持不变。

`scripts/verify_scheduler.py` 在独立空数据库上验证后台启动、重复启动、PID 保护、协作停止、重启，以及停止采集不影响网页。浏览器验收使用独立真实数据副本；模拟故障/恢复只写入该副本。

本轮功能测试和短时运行不能代替连续 48 小时观察。长时间休眠、长期断网、Token 限额和上游页面变化仍需持续监测；未新增消息通知或自动模型下载。
